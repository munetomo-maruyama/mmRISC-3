## 0. 要約

1. **目標: CoreMark/MHzの最大化。クロックにはこだわらない。** 100 MHzは断念した(作者、2026-11-05)。そのあとは、これまでどおりmicroSDスロットJ3からBusyBoxとDebian 13、Ethernet(RTL8211E)、Pmod JAのJTAG / cJTAG。
2. **CPUは50 MHz、LiteXは100 MHz**(作者、2026-11-05。4.4)。50 MHzは、CoreMark/MHzを左右するload-use 2と1サイクルのALUを保てる、閉じると分かっている範囲で最も高いクロック。
3. **構成**: 1サイクルにリネーム、ディスパッチ、コミットが4、32バイトフェッチからデコード6、**ALU 4 + LSU 2、6発行**、ROB 48、LQ / SQ 16、チェックポイント12、TAGE M、uBTB 96、**今のコアと同じ段数**: **これまで作ったとおりのモデルで8.63、RTLで約8.1(× 0.94)、約406 CoreMark/秒**。今のコアの実測は5.50、275。
4. **半分の速度の島はなくなる**: CPU全体が1つのクロックで、L1のヒットの経路はmmRISC-2のまま。
5. **まだ測っていないもの**: この命令幅の20 ns、LUT(見積もり約110k、82 %で上限超え)。100 MHzのときと同じく、**6つのループをまず測る**(4.5)。それぞれに代償の分かった代替案がある。

## 4. 50 MHzのマイクロアーキテクチャ

### 4.1 1サイクルに入るもの

20 nsからクロック出力遅延、セットアップ、不確かさを引くと約19.3 ns。今の2命令幅のコアはそこで余裕少なく閉じている: **20 nsの目標でWNS +0.159 ns、10 nsの目標で約18.8 ns**で、限界はブロック間の経路(`Plan/OOC_J.md` 28.26)。Vivadoは目標を満たすと止まるので、20 nsでのブロックの結果は上限にすぎない。10 nsの目標では9〜15 nsに届く(`Plan/OOC_J.md` 28.1)。

### 4.2 構成

| 項目 | 今 | **提案** | 理由 |
|---|---|---|---|
| フェッチ | 16 B、3段 | **32 B、3段** | デコード6と合わせて+9.5 % |
| デコード | 4 | **6** | フェッチブロックをまたぐ。1サイクルに1ブロックは−2.2 % |
| デコードとリネームの間 | グループのレジスタ | **デコード済み命令のキュー** | 6入れて4出す |
| **リネーム、ディスパッチ、コミット** | 2 | **4**、1サイクルにチェックポイント2つ(`OOO_RENAME2`) | モデルでは2つで損がない |
| **発行キュー** | 統合10、3発行 | **統合24、6発行** | 分散は−2.4 %で、代替案(`OOO_SCHED`) |
| ALU | フル1、限定1 | **4**: `OOO_ALUF` 3つとフル1つ | ALU 3は−3.5 %。遅い演算を1ポートに置く代償はここではまだモデルにない。100 MHzではCoreMarkで−0.1 % |
| LSUポート | 1 | **2** | 1ポートは−8.0 % |
| 分岐 | EX + 1で比較して動く | **同じ** | |
| load-use | 2 | **2** | 3は−12.7 %: **クロックを決めるのはこれ** |
| 乗算 | 2 | **2、パイプライン**(`OOO_PMUL`) | |
| ストア | 1 µop、データと一緒 | **同じ** | リプレイありの分割は−8.4 %。リプレイなしの+2.6 %は実現できない(`Plan/OOC_J.md` 29) |
| ROB / LQ、SQ / チェックポイント | 24 / 8 / 6 | **48 / 16 / 12**、レジスタ**80** | |
| レジスタファイル | 3ライト、6リード | **6ライト、11リード** | LUTで最大の未知数 |
| 予測器 | TAGE S、uBTB 8 | **TAGE M、uBTB 96**(`OOO_UBTB2`) | |
| フュージョン | オフ | **オフ** | +0.7 %: S1-Bのあとの手段 |

### 4.4 各ブロックのクロック

DDR3が決めるのはLiteXのクロックで、CPUのクロックではない。CPUがチップのほかの部分と接するのはバスの乗り換えだけ。

| ブロック | クロック | 理由 |
|---|---|---|
| ボードの発振器、R4 | 100 MHz | MMCMの入力 |
| **コア全体、L1** | **50 MHz** | 1章 |
| FPU、MDU、CSR、PTW、PMP | **50 MHz** | CPUと同じクロック: 半分の速度の島は不要。`OOO_CPU`で20 nsを満たしている |
| L2、デバッグ、CLINT、PLIC | **50 MHz** | `mtime`は分周100で、これまでどおり500 kHz |
| **バスの乗り換え** | 50 / 100 MHz | `AXIClockDomainCrossing`、`AXILiteClockDomainCrossing`。立ち上げのmmRISC-2と同じ。遅延が効くのはミスのときだけで、2.5で測る |
| **LiteXの`sys`**: LiteDRAM、CSR、UART、SDの論理、LiteEthのバス側 | **100 MHz** | DDR3-800、このボードのLiteXの既定。JEDECの下限303 MHzから1:4で約76 MHz以上、800 MT/sから1:4で最大100 MHz |
| `sys4x`、`sys4x_dqs` | 400 MHz、位相90°の400 MHz | DDR3-800 |
| IDELAYCTRL | 200 MHz | DDR3とRGMIIの受信遅延 |
| RGMII | 125 MHz | `LiteEthPHYRGMII`は1 Gb/s専用で、PHYの受信クロックから作る |
| microSD | 25 MHz、そのあと最大50 MHz | `sys`のLiteSDCardの分周。3.3 Vのみ |
| JTAG / cJTAG、Pmod JA | 最大10 MHz、非同期 | JAの200 Ω直列抵抗 |

1つのMMCMの例: VCO 800 MHzから、100 MHz(/8)、400 MHz(/2)、位相90°の400 MHz(/2)、200 MHz(/4)、50 MHz(/16)。Vivadoではまだ確認していない。

### 4.5 決め手になる6つのループ

| # | ループ | 目標 | だめなら | モデル | 今分かっていること |
|---|---|---|---|---|---|
| 1 | **ウェイクアップ + 選択** | 1サイクル、統合24、6選択 | 分散キュー(`OOO_SCHED`) | −2.4 % | 今のものは11.8 ns、10エントリ、3ポート。`OOO_SCHED`は8.9 ns、各8エントリ。**`OOO_IQ2`、制約込みのモデルで8.63: 15 nsの要求で約15.6 ns、ペイロードなしで8,888 LUT**(`Plan/OOC_J.md` 29.3)。単体 |
| 2 | **バイパス + ALU + レジスタファイル** | RRとEX、結果6つ、11リード、6ライト | ALU 3。レジスタファイルを100 MHzのクロックで2回使う | −3.5 % | `OOO_EXU`と`OOO_PRF2`で1段9.2 ns、12,472 LUT、ALU 3、4ライト、8リード。**`OOO_EXU2`、バイパス1段: 15 nsを満たす、20,332 LUT、うちレジスタファイル12,839**(`Plan/OOC_J.md` 29.6)。単体 |
| 3 | **ロード** | load-use 2、2ポート | LSU 1。load-use 3 | −8.0 %、−12.7 % | 今のものは12.6 ns、1ポート。**作成済み: `OOO_LSU3`、ポートごとにD$の配列のコピー。`synth_ooo.bat lsu3`で実行**(`Plan/OOC_J.md` 29.7) |
| 4 | **フェッチ** | 32 B、3段、オーバーライドはF2 | 1段追加、オーバーライドもそれとともに | −2.1 % | 今のものは14.3 ns、16 B。`OOC_FE2`は1段9.5 ns、5段 |
| 5 | **フェッチバッファ** | 1サイクルに6、ブロックをまたぐ | 1サイクルに1ブロック(`OOO_FBUF2`のまま) | −2.2 % | `OOO_FBUF2`は8.65 ns、1ブロック |
| 6 | **4つのリネーム** | 1段 | 1段追加 | −0.5 % | `OOO_RENAME2`は2段で9.1 ns |

ブロック間については、100 MHz用に提案した4つの切断(`Plan/OOC_J.md` 28.26)は今は不要で、20 nsの結果が求めるときだけ行う。

### 4.6 100 MHz用に作ったもの

| ブロック | 50 MHzでは |
|---|---|
| `OOO_CORE`のRR1 | **取り除いた**(`Plan/OOC_J.md` 29): モデルで−1.1 %、実測で+2.20 %サイクル |

| `OOO_ALUF` | 3つのポートで**使う** |

## 8. リスク

| リスク | 影響 | 対策 |
|---|---|---|
| **LUT: 107.7kに対して約110k**、測定済みはキューとループ2 | ポートを減らす | S1-Aで測る。ALU 3、分散キュー、統合16、レジスタファイルを2回使う |
