# RTL/CPU/CACHE

[English](README.md)

mmRISC-2 Rev.02のL1データキャッシュを、mmRISC-3のために持ってきたもの(`Doc/UARCH_J.md` 3.7: D$はmmRISC-2のものをアダプタの後ろに置く)、とそのL2(手順1.7 H2、`Plan/OOC_J.md` 29.57。仕様はmmRISC-2の`RTL/CPU/CPU_L2/CPU_L2_SPEC_J.md`)。仕様はmmRISC-2の`RTL/CPU/CPU_CACHE/CPU_CACHE_SPEC_J.md`。各ファイルには、どこから来たかを書いた行をヘッダに加えた。

| ブロック | 内容 | mmRISC-2からの変更 |
|---|---|---|
| `DCACHE` | 物理インデックス・物理タグ、4ウェイ × 64セット × 64バイト、ライトバック + ライトアロケート、MSHR 2(ノンブロッキング)、ライトバックバッファ2、要求の順に答える、AXI4のメモリバスとAXI4-Liteの周辺バス | **出力を1つ加えた**: `d_hit_now` / `d_hit_now_data`、ステージ1でのロードのヒットを見つけたそのサイクルに出す(ミスの下でも)。`OOO_DCAD`がLSUのMに渡す(`Plan/OOC_J.md` 17.2)。答えは今までどおり`d_resp_*`にも順に出る。**シミュレーションのため**(`DCACHE_SIM_UC`): `sim_uc_line`、キャッシュしないライン1つ(MEM_BASEより下と同じ)、テストベンチの`tohost`(`Plan/CORE_J.md` 5.5、B3-6) |
| `CACHE_TAG_ARRAY` | タグ(メモリ、同期読み出し)とvalid / dirtyのビット(フリップフロップ) | なし |
| `CACHE_DATA_ARRAY` | 64ビットの語、ウェイごとにブロックRAM 1つ、バイトの書き込みイネーブル | **`WR_REG`**(手順1.7c C3、`Plan/OOC.md` 29.70): 1で書き込みポート(アドレス、データ、ストローブ、ウェイごとのイネーブル)をレジスタで受け、ブロックRAMをFFから書く。書き込みは1サイクル遅れる。0(既定)は元のまま(`DCACHE`) |
| `CPU_L2` | L2: 256 KB、4ウェイ(手順1.7c C3から`OOO_CPU`では512 KB)、64バイトのライン、ライトバック、疑似LRU、非包含。トランザクションは1つずつ。1ラインの追い出しバッファを横で書き出す。両側AXI4 | **ヒットした部分書き込みはラインに書いてダーティにし、メモリなしで答える**(前はメモリへも通し、ラインのダーティビットはそのままだった): mmRISC-3のD$はライトスルーなので、すべてのストアが部分書き込みとして来る。ミスした部分書き込みは前と同じくメモリへ。**手順1.7c C3から**データ配列の書き込みポートをレジスタで受ける(`WR_REG`)。そのレジスタが書き込みを持つ間(フィルの最後のビートの後だけ)、読み出しは1サイクル待つ |
| `L2_TAG_ARRAY` | L2の{valid, dirty, tag}、ウェイごとにブロックRAM 1つ | なし |

- テスト: `SIM/OOO_UNIT/tb_dcad`(`OOO_LSU`、`OOO_DCAD`、`DCACHE`とAXI4のメモリのモデル)。mmRISC-2自身のキャッシュのテスト(`SIM/SIM_CACHE`)はここでは繰り返さない。加えた出力は2行の論理。
- L2のテスト: `SIM/L2`(`run.sh`: `OOO_MARB`の2つのポートを前に置いたmmRISC-2の`tb_L2`、6つの構成。`mutate.py`: `CPU_L2`、`CACHE_DATA_ARRAY`、`OOO_MARB`のミューテーション51、51検出。設計の構成は手順1.7c C3から512 KB)。
- lintの警告(フィールドを取り出す関数の使われないアドレスのビット、使われないパラメータ)はmmRISC-2のもの。
- `SIM/OOO_UNIT/mutate.py`はこれらのファイルも壊せる(`CACHE:`の項目)。1件、検出。
