# RTL/CPU/OOO

[日本語](README_J.md)

The first blocks of mmRISC-3's out-of-order core in the **fusion configuration** (`Doc/STRATEGY.md` section 4): the
loops that have to close in one cycle at 50 MHz and the parts whose cost decides the configuration. They are written
to be used as they are in Phase 1, and are measured alone first (Phase 0, step 3 of `Plan/ISSUES.md`; results in
`Plan/OOC.md`).

| Block | What it is | Test (`SIM/OOO_UNIT`) |
|---|---|---|
| `OOO_ALU` | One integer ALU: RV64I + Zba / Zbb / Zbs / Zicond, the operation set and encoding of mmRISC-2's CORE_EXU; the adder and the shifter are shared between operations; `FULL = 0` is ALU1's (add / sub, slt / sltu, logic: G0b L7) | through OOO_ALU2 |
| `OOO_ALU2` | The ALU of one issue port: a full `OOO_ALU` (or ALU1's limited one, `FULL = 0`) and the branch comparison (alone, or for a fused ALU + branch on the ALU result against s1, s2 or zero); 2 sources (fusion level 2) | `tb_alu2` / `tb_alu1`: 2,000,000 random vectors each against the specification |
| `OOO_BTB` | Branch target buffer for indirect jumps only: 256 rows in block RAM read with the fetch address, one jump per line | `tb_btb`: against a reference table |
| `OOO_CORE` | **The core** (step 4, `Plan/CORE.md` 5.4 / 5.5: B2, ALU µops; B3, port 2 with OOO_LSU and the LSU's abstract D$ port): OOO_FRONT; D2 (the group rotated to its oldest slot, OOO_FUSE with fusion off, OOO_RENAME, the control's go); OOO_DSREG with the µop's payload; OOO_ROB, OOO_IQ, OOO_IQPL; OOO_PRF; two ALU ports (OOO_STAGE RR / EX / WB, the bypass from the WB registers, OOO_ALU2, branch resolution against the prediction and the target array); commit; the commit trace (`OOO_TRACE`) | `SIM/CORE/tb_core`: B2's programs in lock-step with Spike, the resolution against the instructions |
| `OOO_CPU` | **The core with its D$** (`Plan/CORE.md` 5.5, B3): OOO_CORE, OOO_DCAD and mmRISC-2's DCACHE on an AXI4 memory bus and an AXI4-Lite peripheral bus; the I$ still a port; under DCACHE_SIM_UC one line not cached (the bench's `tohost`) | `SIM/CORE/tb_core` (`build_core.sh cpu`): B2's and B3's programs in lock-step on AXI models |
| `OOO_CTRL` | The control: branch masks (a bit per checkpoint), the go of renaming (a free checkpoint id) and of dispatch (room for the DS register's µops), the checkpoint table (LSU tails, FTQ index), recovery in the order trap / replay / restore with kill and clr (the back end flushed a cycle after a trap / replay), the redirect pc, `ns_ok` for non-speculative µops, the commit fan-out and the FTQ's pops (one a cycle: one TAGE update a cycle), `ds_load` (the DS register's payload enable), `restore_port`, `ns_busy` | `tb_ctrl`: an account of the µops in program order with renaming's ring of ids and the ROB played; 4 seeds |
| `OOO_CSRU` | The CSR unit: `CORE_CSR` (`RTL/CPU/CORE`, 2 HPM counters: L1) behind port 0; CSR µops read, check and write in EX at the ROB head (illegal with the instruction as tval; a write completes marked for replay); trap entry, MRET / SRET, the vector, mepc / sepc, the interrupt to take for `OOO_TRAP`, WFI's wakeup | `tb_csru`: a set of CSRs against a reference, L1's counters, minstret 0 to 4 a cycle, trap entry and MRET; 4 seeds |
| `OOO_DCAD` | The D$ adapter between `OOO_LSU` and mmRISC-2's `DCACHE` (`RTL/CPU/CACHE`): loads from E and pending loads, stores, a hit in M from the D$'s stage 1 (`d_hit_now`), the D$'s in-order answers given as fills by LQ entry, the older answers of an entry dropped when it sends again, FENCE.I's FLUSH (`fl_req` / `fl_done`) | `tb_dcad`: the LSU, the adapter and the real D$ with an AXI4 memory model, tb_lsu's core model; 5 seeds in two line layouts |
| `OOO_DEC` | Decode of 4 instructions: `CORE_DECOMP` + `CORE_DEC` per slot (taken from mmRISC-2, `RTL/CPU/CORE`), and the fields for fusion (class, kind, integer registers), the issue queue (port, latency, answer from outside) and the ROB (illegal, non-speculative); the rare classes in slot 0 only (`cut`, from `OOO_RARE`, ends the group before one in slots 1 to 3); illegal in every slot | `tb_dec`: every RVC encoding and 3,000,000 instructions against a decoder from the specification, Spike judging what exists |
| `OOO_DSREG` | The DS register's payload (between renaming and dispatch): the two µops' source tags, ready bits and W bits of everything else; the ready bits snoop the issue queue's wakeup tags of the cycle before, so that a µop held there misses no wakeup | `tb_dsreg`: every source's ready bit against the cycle its producer woke, with renaming's busy bits played, 4 seeds |
| `OOO_FBUF` | Fetch buffer: a queue of 4 whole 16-byte blocks (start / end parcel, taken, FTQ index), a window of 8 parcels over the head block and the next, up to 4 instructions a cycle (RVC or 32-bit, also across blocks); `free_n` for fetch's credit; `out_rare` (`OOO_RARE` on each of the window's parcels, taken with the instruction's length bit, `Plan/OOC.md` 26.11) | `tb_fbuf`: an execution model with random taken transfers, flushes and partial takes; the exact count given; `out_rare` against a predecode written in the test; 9 seeds |
| `OOO_FERS` | The front end's restore: the point of a redirect (a mispredicted transfer from its ALU port, or the µop of a trap / replay from the ROB) taken in cycle R, its block's FTQ entry read in R + 1 and fetch restarted with the history (slot branches up to the point) and the RAS (snapshot, the point's push / pop): one cycle after the resolution (D-15) | `tb_fers`: blocks built from their instructions, redirects at any instruction, often back to back; 4 seeds |
| `OOO_FTQ` | Fetch target queue: 16 entries (D-18; 8 before) (fetch address, next address, taken parcel, predictor state) in LUTRAM, 2 reads for decode, 1 for the restore and the head's for the TAGE update; pop / restore / flush_all; `free_n` | `tb_ftq`: against a reference queue, 4 seeds |
| `OOO_RARE` | Whether an instruction is of a rare class (decoded in slot 0 only), from its first parcel alone: the 32-bit major opcodes LOAD-FP, STORE-FP, FMA, OP-FP, AMO, MISC-MEM, SYSTEM; c.fld / c.fsd / c.fldsp / c.fsdsp / c.ebreak. A few gates, for the fetch buffer's count taken (`Plan/OOC.md` 26; on the window's parcels in OOO_FBUF, 26.11) | `tb_dec`: every legal instruction of the rare classes caught, `cut` as a predecode written in the test |
| `OOO_FRONT` | **The front end put together** (B1, `Plan/CORE.md` 5.2): OOO_FETCH, the FTQ with 312 bits a block, OOO_FERS, OOO_FBUF, the raw register R of D1a with a skid of one raw group, OOO_DEC in D1b and the group register (4 decoded instructions with pc, block, last parcel); the fetch buffer's group cut at its `out_rare`; credit; the outcomes of the slot branches by block and parcel for the TAGE update at the FTQ's pop (to TAGE a cycle later from a register, `Plan/OOC.md` 26.14 A); the target array and the pc array (two reads each, for the ALU ports) | `SIM/CORE/tb_front`: riscv-tests and CoreMark fetched and decoded against Spike's path, every TAGE update checked |
| `OOO_FETCH` | The front end F0–F2 around `OOO_UBTB`, `OOO_PREDEC`, `OOO_TAGE`, `OOO_BTB` and `OOO_RAS`: I$ requests and answers, the first transfer predicted taken ends the block, F2 overrides the uBTB (2 cycles) and trains it a cycle later from a register (`Plan/OOC.md` 26.14 B), recovery from the back end (`be_stop` in the cycle of the back end's redirect, the restart a cycle later from `OOO_FERS`), credit from the fetch buffer and the FTQ | `tb_fetch`: a random program through an I$ with misses, a back end on the true path; every fetch address and every block against mirrors of the predictors, 11 programs |
| `OOO_FUSE` | Fusion: 4 decoded instructions → the next 2 µops (lui + addi, auipc + x, slli + srli, ALU + load, load / store pairs, ALU + branch: level 2); a pair reads at most 2 sources and writes at most 1 register | `tb_fuse`: random against the rules; on the CoreMark stream exactly the model's pairs |
| `OOO_IQ` | Issue queue: 10 entries, 2 sources and 1 destination per µop, 6 wakeup buses, 2 in / 3 out per cycle (ALU0 + MUL/DIV, ALU1, LSU), 1-cycle wakeup-select, oldest first by an age matrix (port 1 selecting first), latency-2 and external wakeups (none delayed for a µop killed or flushed as it issues), the wakeup tags out (`wk_*`: renaming's busy bits, the DS register), entries freed at issue (a load that misses is replayed after commit by the ROB), a branch mask per entry (kill, clr, `iss_bm`), non-speculative µops only at the ROB head (`ns_ok`); MDU µops only with `mdu_ok`, port 0's write slot kept for the multiply and the MDU's waiting results; `disp_entry` / `iss_entry` for the payload | `tb_iq`: every issue, its entry, its mask, the wakeup buses and the free entries against an independent account of when values are usable, with kills and clears; 6 seeds |
| `OOO_IQPL` | The issue queue's payload: one W-bit record per entry (16 × 96), 2 writes at DS / 3 reads in RR (port 2 the low 48 bits only), two LUTRAM banks with one write port each and a live value table | `tb_iqpl`: random writes and reads against an array, 4 seeds |
| `OOO_RAS` | Return address stack: 16 entries in LUTRAM, recovery from a block's snapshot (pointer and the entry a push overwrites) | `tb_ras`: against a reference stack |
| `OOO_RENAME` | Renaming: 2 µops per cycle with 2 sources and 1 destination, 64 physical registers, RAT, free list, busy bits (cleared by the issue queue's wakeup tags), in-group dependences, 6 checkpoints in a ring of 6 copied a cycle late, the committed-state RAT for `flush_all`; `ready` from the µops offered, not from `in_valid` (the control's `r_go` waits for it: `Plan/CORE.md` 5.4) | `tb_rename`: against a reference with commits, wakeups and restores |
| `OOO_MDUP` | Port 0's MDU: `CORE_MDU` (`RTL/CPU/CORE`, one operation at a time) for mulh*, clmul* and the divides, written when port 0's write-back slot is free with their wakeup (`ext_*`, `p0_hold`), `mdu_ok` for the issue queue; killed by mask or flush | `tb_mdup`: every operation against the M / Zbc semantics with port 0 played by the queue's rules (muls beside it), kills and flushes; 4 seeds |
| `OOO_PMUL` | The pipelined mul / mulw beside it (D-16 variant A): the low 64 bits from three 32 × 32 products in DSP blocks, latency 2, one a cycle; killed by mask or flush in either cycle | `tb_pmul`: back-to-back muls against the product, kills and flushes; 4 seeds |
| `OOO_PREDEC` | Predecode (F2): instruction boundaries (with a 32-bit instruction carried from the line before), the kind of each control transfer and the targets of branches and jal, 8 adders in parallel | `tb_predec`: 2,000,000 random blocks against a reference from the specification |
| `OOO_PRF` | Physical registers: NREG × 64 (64 in the fusion configuration), NW writes / NR reads (3 / 6), LUTRAM banks + live value table | `tb_prf`: random reads and writes against an array |
| `OOO_LSU` | Load / store unit: LQ 8, SQ 8 (G0b L4), `rf_*` (its M result for the register file, `Plan/CORE.md` 4.2), forwarding from the youngest older store, conservative ordering (`lsu_st_known`), `ld_cancel` and late results for misses (marked `cmp_ld_rp` for replay after commit), recovery to a checkpoint or the committed state, a µop from port 2 dropped by its branch mask in E and M (an older one goes on through a restore), `sq_drained` for the fences | `tb_lsu`: the rest of the core modelled with branch masks and issues in cycles of recovery, every load value against program order, 7 seeds |
| `OOO_ROB` | Reorder buffer: 24 µops, 2 in / 2 committed a cycle, payload in two LUTRAM banks by parity, 4 completion ports, the oldest misprediction of a cycle restores, traps at the head, replay after commit of a marked load (`replay`, `replay_pc`), the fetch block at commit (`cmt_ftq`), `head_ns` for non-speculative µops, the point of a trap / replay for the front end's restore (`rcv_ftq`, `rcv_end`), `irq` (an interrupt before the head), `head_valid`, `head_fused` | `tb_rob`: against a reference ROB, 4 seeds |
| `OOO_STAGE` | One pipeline register of a unit: valid, branch mask and W bits; a µop killed as it is taken or while held (`en` = 0) leaves, cleared bits leave the mask, `flush` empties it | `tb_stage`: against the history of the µop held, ids given out again at once, 4 seeds |
| `OOO_SYS` | The system µops at the ROB head: FENCE (the committed stores drained), FENCE.I (then the D$ FLUSH and the I$ invalidated, replay), SFENCE.VMA (TLB flush, replay), MRET (`x_mret`, replay), WFI (until an interrupt is pending) | `tb_sys`: every µop's steps in order with random answers and abandoned µops; 4 seeds |
| `OOO_TAGE` | TAGE-S per fetch block in block RAM: 4 tagged tables × 1024 rows with 3 slots (the 1st–3rd conditional branch of a block), base per parcel, history from a 70-bit shift register, update at commit from the metadata kept in the FTQ | `tb_tage`: against `tage_ref.h`, every prediction and all metadata, 4 seeds |
| `OOO_TRAP` | Exceptions and interrupts at the ROB head: interrupts at a µop boundary (not under an issued non-speculative µop), the trap's CSR writes (mepc, mcause, mtval of the oldest exception) and vector (vectored for interrupts), the refetch with fusion off after an exception in a pair (`no_fuse`), MRET's replay to mepc | `tb_trap`: inside a model ROB with out-of-order completions, restores, replays, interrupts and stale reports; 4 seeds |
| `OOO_UBTB` | Next-line predictor: 8 entries (G0b L5), 12-bit partial tags, next fetch address in one cycle with a parallel choice | `tb_ubtb`: against a reference table |

- Coding follows mmRISC-2 (`logic`, `always_ff` with active-low asynchronous reset, comments on what and why).
- Every block is linted by Verilator (`-Wall`); the unit tests start everything that has no reset at random values.
- `SIM/OOO_UNIT/mutate.py` breaks the RTL on purpose (293 mutations); all are detected.
- Out-of-context synthesis in Vivado: `FPGA/OOO_OOC` (`synth_ooo.bat`), run by the author.
