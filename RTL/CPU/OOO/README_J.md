# RTL/CPU/OOO

[English](README.md)

mmRISC-3のOoOコアを**融合構成**(`Doc/STRATEGY_J.md` 4章)で作るための最初のブロック群。50MHzで1サイクルに閉じる必要があるループと、構成を決めるコストを持つ部分。Phase 1でそのまま使える形で書き、まず単体で測る(Phase 0、`Plan/ISSUES_J.md` 5章の手順3。結果は`Plan/OOC_J.md`)。

| ブロック | 内容 | テスト(`SIM/OOO_UNIT`) |
|---|---|---|
| `OOO_ALU` | 整数ALU 1つ: RV64I + Zba / Zbb / Zbs / Zicond。操作の種類と符号はmmRISC-2のCORE_EXUと同じ。加算器とシフタを操作の間で共有する。`FULL = 0`はALU1のもの(加減算、slt / sltu、論理: G0bのL7) | OOO_ALU2を通して |
| `OOO_ALU2` | 発行ポート1つ分のALU: フルの`OOO_ALU`(またはALU1の絞ったもの、`FULL = 0`)と分岐の比較(単独、または融合したALU + 分岐でALUの結果をs1、s2、0のどれかと比べる)。ソース2つ(融合レベル2) | `tb_alu2` / `tb_alu1`: 仕様から書いた参照とランダムにそれぞれ200万件 |
| `OOO_BTB` | 間接ジャンプだけのブランチターゲットバッファ: ブロックRAMに256行、フェッチアドレスで読む。1行に1つのジャンプ | `tb_btb`: 参照の表と照合 |
| `OOO_CORE` | **コア**(ステップ4、`Plan/CORE_J.md` 5.4 / 5.5 / 5.7: B2、ALUのµop。B3、OOO_LSUとLSUの抽象的なD$のポートを持つポート2。B4、ポート0のOOO_CSRU、OOO_SYS、OOO_PMUL、OOO_MDUP、OOO_TRAP、デコードでの例外、ROBのエントリごとの命令のビット): OOO_FRONT。D2(いちばん古いスロットへ回したグループ、融合なしのOOO_FUSE、OOO_RENAME、制御のgo)。µopのペイロードを持つOOO_DSREG。OOO_ROB、OOO_IQ、OOO_IQPL。OOO_PRF。2つのALUポート(OOO_STAGEのRR / EX / WB、WBレジスタからのバイパス、OOO_ALU2、予測とターゲットの配列に対する分岐の解決)。コミット。コミットトレース(`OOO_TRACE`) | `SIM/CORE/tb_core`: B2、B3、B4のプログラム(riscv-arch-test、riscv-testsの-p-)をSpikeとlock-stepで、解決を命令と照合 |
| `OOO_CPU` | **D$を持つコア**(`Plan/CORE_J.md` 5.5、B3): AXI4のメモリバスとAXI4-Liteの周辺バスの上のOOO_CORE、OOO_DCAD、mmRISC-2のDCACHE。I$はまだポート。DCACHE_SIM_UCのもとでキャッシュしないライン1つ(ベンチの`tohost`) | `SIM/CORE/tb_core`(`build_core.sh cpu`): B2、B3、B4のプログラムをAXIのモデルの上でlock-stepで |
| `OOO_CTRL` | 制御: ブランチマスク(チェックポイントごとに1ビット)、リネームの進行(空いたチェックポイント番号)とディスパッチの進行(DSレジスタのµopの分の空き)、チェックポイントの表(LSUのtail、FTQの番号)、トラップ / リプレイ / 復元の順の回復とkill・clr(トラップ / リプレイのあと後段は1サイクル遅れてフラッシュ)、リダイレクトのpc、非投機のµopのための`ns_ok`、コミットの後始末とFTQのpop(1サイクルに1つ: TAGEの更新が1サイクルに1つ)、`ds_load`(DSレジスタのペイロードのイネーブル)、`restore_port`、`ns_busy` | `tb_ctrl`: プログラム順のµopの帳簿と、リネームの番号の輪とROBを演じて照合。4シード |
| `OOO_CSRU` | CSRユニット: ポート0の後ろの`CORE_CSR`(`RTL/CPU/CORE`、HPMカウンタ2つ: L1)。CSRのµopはROBの先頭のEXで読み、確かめ、書く(命令をtvalにした不正命令。書くものはリプレイの印つきで完了)。`OOO_TRAP`のためのトラップへの入口、MRET / SRET、ベクタ、mepc / sepc、取る割り込み、WFIの起床。minstretへの書き込みは自分のコミットを数えず、mcountinhibitへの書き込みはそのコミットでCORE_CSRに届く、mstatus.FSがオフならFPのCSRは不正(B4) | `tb_csru`: CSRの組を参照と照合、L1のカウンタ、1サイクルに0〜4のminstret(CSRを書いたあとのコミットは1つだけ)、mcountinhibit、トラップへの入口とMRET。4シード |
| `OOO_DCAD` | `OOO_LSU`とmmRISC-2の`DCACHE`(`RTL/CPU/CACHE`)のあいだのD$のアダプタ: Eのロードと保留のロード、ストア、D$のステージ1からのMでのヒット(`d_hit_now`)、D$の順どおりの答えをLQのエントリごとのフィルとして渡す、エントリが要求を出し直すと古い答えを捨てる、FENCE.IのFLUSH(`fl_req` / `fl_done`) | `tb_dcad`: LSU、アダプタ、本物のD$とAXI4のメモリのモデル、tb_lsuのコアのモデル。2つのラインの配置で5シード |
| `OOO_DEC` | 4命令のデコード: スロットごとに`CORE_DECOMP` + `CORE_DEC`(mmRISC-2から持ってきたもの、`RTL/CPU/CORE`)と、融合(種類、op、整数レジスタ)、発行キュー(ポート、レイテンシ、外からの答え)、ROB(illegal、非投機)のためのフィールド。まれな種類はスロット0だけ(スロット1〜3にあれば、`OOO_RARE`からの`cut`でグループをその前で終える)。illegalはすべてのスロットで | `tb_dec`: すべてのRVCの符号と300万命令を、仕様から書いたデコーダと照合。存在するかはSpikeが判定 |
| `OOO_DSREG` | DSレジスタのペイロード(リネームとディスパッチのあいだ): 2つのµopのソースのタグ、readyビット、ほかのすべてのWビット。readyビットは発行キューの前のサイクルのwakeupのタグを見張るので、ここで待つµopはwakeupを逃さない | `tb_dsreg`: リネームのbusyビットを演じ、すべてのソースのreadyビットをその生産者がwakeupしたサイクルと照合。4シード |
| `OOO_FBUF` | フェッチバッファ: 16バイトのブロックを丸ごと4つ並べるキュー(最初 / 最後のパーセル、taken、FTQ番号)、先頭のブロックと次のブロックにかかる8パーセルの窓、1サイクルに最大4命令(RVCか32ビット、ブロックをまたぐものも)。フェッチのクレジット用の`free_n`。`out_rare`(窓の各パーセルにかけた`OOO_RARE`を、命令長のビットといっしょに取る、`Plan/OOC_J.md` 26.11) | `tb_fbuf`: ランダムなtaken転送・フラッシュ・一部だけの取り出しを含む実行のモデル。出す数そのものを照合。`out_rare`をテストに書いたプリデコードと照合。9シード |
| `OOO_FERS` | フロントエンドの復元: リダイレクトの地点(ALUポートからの予測ミスした転送か、ROBからのトラップ / リプレイのµop)をサイクルRに取り、R + 1にそのブロックのFTQのエントリを読み、履歴(地点までのスロットの分岐)とRAS(スナップショット、地点のpush / pop)でフェッチを再開する: 解決の1サイクル後(D-15) | `tb_fers`: 命令から作るブロック、どの命令でもリダイレクト、続けて起こすことも多い。4シード |
| `OOO_FTQ` | フェッチターゲットキュー: 16エントリ(D-18。前は8)(フェッチアドレス、次のアドレス、takenのパーセル、予測器の状態)をLUTRAMに。デコード用の読み出し2、復元用1、TAGEの更新用の先頭の読み出し。pop / restore / flush_all。`free_n` | `tb_ftq`: 参照のキューと照合。4シード |
| `OOO_RARE` | 命令がまれな種類(スロット0だけでデコード)かを、最初のパーセルだけから: 32ビットのメジャーオペコードLOAD-FP、STORE-FP、FMA、OP-FP、AMO、MISC-MEM、SYSTEM。c.fld / c.fsd / c.fldsp / c.fsdsp / c.ebreak。フェッチバッファの取る数のための数ゲート(`Plan/OOC_J.md` 26。OOO_FBUFの中で窓のパーセルに、26.11) | `tb_dec`: まれな種類の正しい命令をすべて捕らえること、`cut`をテストに書いたプリデコードと照合 |
| `OOO_FRONT` | **組み上げたフロントエンド**(B1、`Plan/CORE_J.md` 5.2): OOO_FETCH、1ブロック312ビットのFTQ、OOO_FERS、OOO_FBUF、D1aの生のレジスタRと生のグループ1つのスキッド、D1bのOOO_DECとグループのレジスタ(デコードした4命令とpc、ブロック、最後のパーセル)。フェッチバッファのグループはその`out_rare`で切る。クレジット。FTQのpopでのTAGEの更新のための、ブロックとパーセルごとのスロットの分岐の結果(TAGEへは1サイクル後にレジスタから、`Plan/OOC_J.md` 26.14 A)。ターゲットの配列とpcの配列(ALUポートのためにそれぞれ2つの読み出し) | `SIM/CORE/tb_front`: riscv-testsとCoreMarkをフェッチ・デコードしてSpikeの経路と照合、TAGEの更新をすべて照合 |
| `OOO_FETCH` | `OOO_UBTB`、`OOO_PREDEC`、`OOO_TAGE`、`OOO_BTB`、`OOO_RAS`を囲むF0〜F2のフロントエンド: I$への要求と答え、最初にtakenと予測された転送でブロックを終える、F2がuBTBを上書きして(2サイクル)、1サイクル後にレジスタから学習させる(`Plan/OOC_J.md` 26.14 B)、バックエンドからの回復(後段のリダイレクトのサイクルに`be_stop`、1サイクル後に`OOO_FERS`から再開)、フェッチバッファとFTQからのクレジット | `tb_fetch`: ミスのあるI$を通してランダムなプログラムを走らせ、バックエンドが本当の経路をたどる。毎サイクルのフェッチアドレスとすべてのブロックを予測器のミラーと照合。11プログラム |
| `OOO_FUSE` | 融合: デコードした4命令 → 次の2 µop(lui + addi、auipc + x、slli + srli、ALU + ロード、ロード / ストアのペア、ALU + 分岐: レベル2)。組のソースは2本まで・書き込みは1本まで | `tb_fuse`: 規則の参照とランダム。CoreMarkの命令列でモデルの組をちょうど作る |
| `OOO_IQ` | 発行キュー(より古いストアがキューにあるあいだロードは待つ、`Plan/CORE_J.md` 5.9): 10エントリ、µopあたりソース2・デスティネーション1、wakeupバス6本、1サイクルに2入 / 3出(ALU0 + MUL/DIV、ALU1、LSU)、1サイクルのwakeup-select、age matrixで古い順(ポート1が先に選ぶ)、レイテンシ2と外部からのwakeup(発行と同時にkillかフラッシュされたµopの遅れたwakeupは出さない)、wakeupのタグを外へ(`wk_*`: リネームのbusyビット、DSレジスタ)。エントリは発行で空く(ミスしたロードはROBがコミットのあとにリプレイ)。エントリごとのブランチマスク(kill、clr、`iss_bm`)。非投機のµopはROBの先頭でだけ(`ns_ok`)。MDUのµopは`mdu_ok`のときだけ、ポート0の書き込みの枠は乗算とMDUの待つ結果のために空ける。ペイロードのための`disp_entry` / `iss_entry` | `tb_iq`: 値が使える時刻を独立に追った帳簿と、毎サイクルの発行、そのエントリ、そのマスク、wakeupのバス、空きエントリを照合。killと消去を含む。6シード |
| `OOO_IQPL` | 発行キューのペイロード: エントリごとにWビットの記録1つ(16 × 96)、DSで書き込み2 / RRで読み出し3(ポート2は下位48ビットだけ)、書き込みポート1つのLUTRAMのバンク2つとライブ値表 | `tb_iqpl`: 乱数の書き込みと読み出しを配列と照合、4シード |
| `OOO_RAS` | リターンアドレススタック: LUTRAMに16エントリ。ブロックのスナップショット(ポインタとpushで上書きされるエントリ)から回復 | `tb_ras`: 参照のスタックと照合 |
| `OOO_RENAME` | リネーム: 1サイクルに2 µop、ソース2・デスティネーション1、物理レジスタ64本、RAT、フリーリスト、busyビット(発行キューのwakeupのタグで消す)、同じ組の中の依存、1サイクル遅れて写すチェックポイント6(6の輪)、`flush_all`のためのコミット状態のRAT。`ready`は`in_valid`からではなく差し出されたµopから(制御の`r_go`がそれを待つ: `Plan/CORE_J.md` 5.4) | `tb_rename`: コミット・wakeup・復元を含む参照と照合 |
| `OOO_MDUP` | ポート0のMDU: mulh*、clmul*、除算のための`CORE_MDU`(`RTL/CPU/CORE`、一度に1つの演算)。ポート0の書き戻しの枠が空いたときにwakeupつきで書く(`ext_*`、`p0_hold`)、発行キューへの`mdu_ok`。マスクかフラッシュでkill | `tb_mdup`: キューの規則で演じるポート0(横の乗算あり)、kill、フラッシュつきで、すべての演算をM / Zbcの意味と照合。4シード |
| `OOO_PMUL` | その横のmul / mulwのパイプラインの乗算器(D-16の案A): DSPの32 × 32の積3つから下位64ビット、レイテンシ2、1サイクルに1つ。どちらのサイクルでもマスクかフラッシュでkill | `tb_pmul`: 続けて来る乗算を積と照合、kill、フラッシュ。4シード |
| `OOO_PREDEC` | プリデコード(F2): 命令の境界(前の行から持ち越した32ビット命令も)、制御転送の種類、分岐とjalのターゲット。加算器8つを並列に | `tb_predec`: ランダムな200万ブロックを、仕様から書いた参照と照合 |
| `OOO_PRF` | 物理レジスタ: NREG × 64(融合構成では64本)、書き込みNW / 読み出しNR(3 / 6)、LUTRAMのバンク + LVT | `tb_prf`: 配列とランダムに照合 |
| `OOO_LSU` | ロード / ストアユニット: LQ 8、SQ 8(G0bのL4)、`rf_*`(レジスタファイルのためのMの結果、`Plan/CORE_J.md` 4.2)、コミット済みのストアは、ロードに`DRAIN_WAIT`(8)サイクル止められたらD$のポートを取る(5.6)、いちばん若い古いストアからのフォワーディング、保守的な順序(`lsu_st_known`)、ミスのための`ld_cancel`と遅れた結果(コミットのあとのリプレイのため`cmp_ld_rp`の印つき)、チェックポイントかコミット状態への回復、ポート2のµopはEとMでブランチマスクにより捨てる(古いものは復元をそのまま通る)、フェンスのための`sq_drained` | `tb_lsu`: コアの残りをブランチマスクと回復のサイクルの発行つきでモデルにし、すべてのロードの値をプログラム順と照合。7シード |
| `OOO_ROB` | リオーダーバッファ: 24 µop、1サイクルに2入 / 2コミット、ペイロードは偶奇で分けたLUTRAMの2バンク、完了ポート4つ、そのサイクルのいちばん古い予測ミスでrestore、先頭でトラップ、印のついたロードのコミットのあとのリプレイ(`replay`、`replay_pc`)、コミットでのフェッチブロック(`cmt_ftq`)、非投機のµopのための`head_ns`、フロントエンドの復元のためのトラップ / リプレイの地点(`rcv_ftq`、`rcv_end`)、`irq`(先頭の前での割り込み)、`head_valid`、`head_fused` | `tb_rob`: 参照のROBと照合。4シード |
| `OOO_STAGE` | ユニットのパイプラインレジスタ1段: valid、ブランチマスク、Wビット。取り込むときか保持中(`en` = 0)にkillされたµopは去り、消去されたビットはマスクから落ち、`flush`で空になる | `tb_stage`: 保持しているµopの履歴と照合。番号はすぐに出し直す。4シード |
| `OOO_SYS` | ROBの先頭のシステムのµop: FENCE(コミットしたストアを書き終える)、FENCE.I(そのあとD$のFLUSHとI$の無効化、リプレイ)、SFENCE.VMA(TLBのフラッシュ、リプレイ)、MRET(`x_mret`、リプレイ)、WFI(割り込みが保留になるまで) | `tb_sys`: すべてのµopの手順の順序を、乱数の答えと捨てられるµopで照合。4シード |
| `OOO_TAGE` | ブロックRAMに置くフェッチブロック単位のTAGE-S(いつも2ブロック遅れた履歴で読む、D-17。`f0_live`): タグつきの表4つ × 1024行、スロット3つ(ブロックの1〜3つ目の条件分岐)、パーセルごとのベース、70ビットのシフトレジスタからの履歴、FTQに持つメタデータによるコミットでの更新 | `tb_tage`: `tage_ref.h`と、すべての予測とメタデータを照合。4シード |
| `OOO_TRAP` | ROBの先頭の例外と割り込み: µopの境目での割り込み(発行済みの非投機のµopの下では取らない)、トラップのCSRの書き込み(mepc、mcause、いちばん古い例外のmtval)とベクタ(割り込みはベクタモード)、組の中の例外のあと融合を切って取り直す(`no_fuse`)、MRETのmepcへのリプレイ | `tb_trap`: 順不同の完了、復元、リプレイ、割り込み、古い報告つきのモデルのROBの中で照合。4シード |
| `OOO_UBTB` | next-line予測器: 8エントリ(G0bのL5)、12ビットの部分タグ、並列の選択で次のフェッチアドレスを1サイクルで出す | `tb_ubtb`: 参照の表と照合 |

- 書き方はmmRISC-2に合わせた(`logic`、負論理の非同期リセットの`always_ff`、何を・なぜを書くコメント)。
- すべてのブロックをVerilator(`-Wall`)でlintした。単体テストでは、リセットのない状態をすべてランダムな値で始める。
- `SIM/OOO_UNIT/mutate.py`で、RTLをわざと壊す(293件)。すべて検出された。
- VivadoのOOC合成: `FPGA/OOO_OOC`(`synth_ooo.bat`)。作者が実行する。
