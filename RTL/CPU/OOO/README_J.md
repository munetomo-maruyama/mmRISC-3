# RTL/CPU/OOO

[English](README.md)

> **2026-11-15**: ここのコアは[`Doc/UARCH_J.md`](../../../Doc/UARCH_J.md) A章の4命令幅のもの: `OOO_CORE`を囲むキャッシュ込みのコア`OOO_CPU`で、1サイクルに4 µopをリネーム・ディスパッチ・コミットし、6発行、XC7A200Tで50 MHz。使っているブロックは下のとおり。表のほかのもの(2命令幅のコアのもの、100 MHz用に作ったもの)はテストベンチとともに、履歴として、または使っているブロックの出発点として残す(`Doc/STRATEGY_J.md` 4.6)。

**`OOO_CPU`の中**(2026-11-15):

```
OOO_CPU
├─ OOO_CORE
│  ├─ OOO_FRONT: OOO_FETCH2 (OOO_UBTB2, OOO_FDEC2 with OOO_RAS, OOO_TAGE2, OOO_BTB), OOO_FTQ, OOO_FERS,
│  │             OOO_FBUF3 (OOO_RARE), OOO_DEC (CORE_DECOMP, CORE_DEC, OOO_RARE)
│  ├─ OOO_RENAME2, OOO_BUSY, OOO_CTRL, OOO_ROB, OOO_IQ3, OOO_IQPL2, OOO_PRF
│  ├─ ALUポート4つ: OOO_STAGE (RR, EX, WB), OOO_ALU2 (OOO_ALU)
│  ├─ ポート0: OOO_CSRU (CORE_CSR), OOO_SYS, OOO_PMUL, OOO_MDUP (CORE_MDU); OOO_TRAP
│  ├─ リネームするFPU(手順1.8 U2): OOO_FREN, OOO_BUSY (2), OOO_FIQ, OOO_FPUW (FPU_PIPE: RTL/CPU/FPU), OOO_PRF (FP)
│  ├─ OOO_LSU4: OOO_DCH2, ポートごとにOOO_DTLB3とOOO_PMP(手順1.8 V1まではOOO_DTLB2。PMPはP1から)
│  ├─ OOO_PTW(Sv39のウォーカー、手順1.8 V1)
│  └─ OOO_DBG(デバッグ: RTL/CPU/DBGのDebug Moduleに対するハートの側、手順1.8 J1)
├─ OOO_DMISS2
├─ OOO_ICACHE
├─ OOO_MARB
├─ CPU_L2 (CACHE_DATA_ARRAY, L2_TAG_ARRAY: RTL/CPU/CACHE)
└─ CPU_MMIO (CPU_CLINT, CPU_PLIC: RTL/CPU/MMIO, step 1.8 I1)
```

表はすべてのブロックを作った順に挙げる。最初は、mmRISC-3のOoOコアを**融合構成**(`Plan/STRATEGY_A100T_J.md` 4章)で作るための最初のブロック群。50MHzで1サイクルに閉じる必要があるループと、構成を決めるコストを持つ部分。Phase 1でそのまま使える形で書き、まず単体で測る(Phase 0、`Plan/ISSUES_J.md` 5章の手順3。結果は`Plan/OOC_J.md`)。
