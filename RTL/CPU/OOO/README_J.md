# RTL/CPU/OOO

[English](README.md)

mmRISC-3のOoOコアを**融合構成**(`Doc/STRATEGY_J.md` 4章)で作るための最初のブロック群。50MHzで1サイクルに閉じる必要があるループと、構成を決めるコストを持つ部分。Phase 1でそのまま使える形で書き、まず単体で測る(Phase 0、`Plan/ISSUES_J.md` 5章の手順3。結果は`Plan/OOC_J.md`)。

| ブロック | 内容 | テスト(`SIM/OOO_UNIT`) |
|---|---|---|
| `OOO_ALU` | 整数ALU 1つ: RV64I + Zba / Zbb / Zbs / Zicond。操作の種類と符号はmmRISC-2のCORE_EXUと同じ。加算器とシフタを操作の間で共有する。`FULL = 0`は融合の2段目用に絞ったもの | OOO_ALU2を通して |
| `OOO_ALU2` | 発行ポート1つ分のALU: フルの`OOO_ALU`と絞った`OOO_ALU`を直列にして、融合したALU + ALUを1サイクルで終える。分岐の比較(単独、または融合したALU + 分岐で1段目の結果と比べる) | `tb_alu2`: 仕様から書いた参照とランダムに200万件 |
| `OOO_BTB` | 間接ジャンプだけのブランチターゲットバッファ: ブロックRAMに256行、フェッチアドレスで読む。1行に1つのジャンプ | `tb_btb`: 参照の表と照合 |
| `OOO_FBUF` | フェッチバッファ: 16バイトのブロックを丸ごと4つ並べるキュー(最初 / 最後のパーセル、taken、FTQ番号)、先頭のブロックと次のブロックにかかる8パーセルの窓、1サイクルに最大4命令(RVCか32ビット、ブロックをまたぐものも) | `tb_fbuf`: ランダムなtaken転送・フラッシュ・一部だけの取り出しを含む実行のモデル。出す数そのものを照合。9シード |
| `OOO_FTQ` | フェッチターゲットキュー: 8エントリ(フェッチアドレス、次のアドレス、takenのパーセル、予測器の状態)をLUTRAMに。デコード用の読み出し2、解決用1、pop / restore / flush_all | `tb_ftq`: 参照のキューと照合。4シード |
| `OOO_FETCH` | `OOO_UBTB`、`OOO_PREDEC`、`OOO_TAGE`、`OOO_BTB`、`OOO_RAS`を囲むF0〜F2のフロントエンド: I$への要求と答え、最初にtakenと予測された転送でブロックを終える、F2がuBTBを上書きして(2サイクル)学習させる、バックエンドからの回復、フェッチバッファとFTQからのクレジット | `tb_fetch`: ミスのあるI$を通してランダムなプログラムを走らせ、バックエンドが本当の経路をたどる。毎サイクルのフェッチアドレスとすべてのブロックを予測器のミラーと照合。11プログラム |
| `OOO_FUSE` | 融合: デコードした4命令 → 次の2 µop(lui + addi、auipc + x、slli + srli、ALU + ロード、ロード / ストアのペア、ALU + 分岐、ALU + ALU)。組のソースは2本まで・書き込みは1本まで、ALU + ALUの後半は2段目に置ける操作だけ | `tb_fuse`: 規則の参照とランダム。CoreMarkの命令列でモデルの組の99.99%以上を作る |
| `OOO_IQ` | 発行キュー: 16エントリ、µopあたりソース2・デスティネーション1、wakeupバス6本、1サイクルに2入 / 3出(ALU0 + MUL/DIV、ALU1、LSU)、1サイクルのwakeup-select、age matrixで古い順、レイテンシ2と外部からのwakeup | `tb_iq`: 値が使える時刻を独立に追った帳簿と、毎サイクルの発行を照合 |
| `OOO_RAS` | リターンアドレススタック: LUTRAMに16エントリ。ブロックのスナップショット(ポインタとpushで上書きされるエントリ)から回復 | `tb_ras`: 参照のスタックと照合 |
| `OOO_RENAME` | リネーム: 1サイクルに2 µop、ソース2・デスティネーション1、物理レジスタ64本、RAT、フリーリスト、busyビット、同じ組の中の依存、1サイクル遅れて写すチェックポイント8、`flush_all`のためのコミット状態のRAT | `tb_rename`: コミット・書き戻し・復元を含む参照と照合 |
| `OOO_PREDEC` | プリデコード(F2): 命令の境界(前の行から持ち越した32ビット命令も)、制御転送の種類、分岐とjalのターゲット。加算器8つを並列に | `tb_predec`: ランダムな200万ブロックを、仕様から書いた参照と照合 |
| `OOO_PRF` | 物理レジスタ: NREG × 64(融合構成では64本)、書き込みNW / 読み出しNR(3 / 6)、LUTRAMのバンク + LVT | `tb_prf`: 配列とランダムに照合 |
| `OOO_LSU` | ロード / ストアユニット: LQ 12、SQ 12、いちばん若い古いストアからのフォワーディング、保守的な順序(`lsu_st_known`)、ミスのための`ld_cancel`と遅れた結果、チェックポイントかコミット状態への回復 | `tb_lsu`: コアの残りをモデルにし、すべてのロードの値をプログラム順と照合。7シード |
| `OOO_ROB` | リオーダーバッファ: 24 µop、1サイクルに2入 / 2コミット、ペイロードは偶奇で分けたLUTRAMの2バンク、完了ポート4つ、そのサイクルのいちばん古い予測ミスでrestore、先頭でトラップ、非投機のµopのための`head_ns` | `tb_rob`: 参照のROBと照合。4シード |
| `OOO_TAGE` | ブロックRAMに置くフェッチブロック単位のTAGE-S: タグつきの表4つ × 1024行、スロット3つ(ブロックの1〜3つ目の条件分岐)、パーセルごとのベース、70ビットのシフトレジスタからの履歴、FTQに持つメタデータによるコミットでの更新 | `tb_tage`: `tage_ref.h`と、すべての予測とメタデータを照合。4シード |
| `OOO_UBTB` | next-line予測器: 16エントリ、12ビットの部分タグ、並列の選択で次のフェッチアドレスを1サイクルで出す | `tb_ubtb`: 参照の表と照合 |

- 書き方はmmRISC-2に合わせた(`logic`、負論理の非同期リセットの`always_ff`、何を・なぜを書くコメント)。
- すべてのブロックをVerilator(`-Wall`)でlintした。単体テストでは、リセットのない状態をすべてランダムな値で始める。
- `SIM/OOO_UNIT/mutate.py`で、RTLをわざと壊す(125件)。すべて検出された。
- VivadoのOOC合成: `FPGA/OOO_OOC`(`synth_ooo.bat`)。作者が実行する。
